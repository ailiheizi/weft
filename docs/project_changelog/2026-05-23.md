# 2026-05-23 项目更新日志

> 本次更新涉及 core、agent-core、weft-claw、session-events、weft_client 五个仓库/模块。
> 核心目标：实现 Flutter 客户端工具调用实时展示，彻底解决"等全部跑完才显示"的问题。

## core

### 新增：`/api/stream/events` lock-free 端点

- 文件：`src/api/mod.rs`
- 新增 `GET /api/stream/events?session_id=xxx&after_seq=N` 端点
- 直接用 rusqlite 读 SQLite，完全绕过 WASM 执行锁
- 解决了 `send_message` 执行期间轮询事件被阻塞的根本问题
- 验证：`send_message` 执行期间 poll 响应时间 < 300ms，事件实时可读

## packages/official/session-events（无独立 git 仓库）

### 修复：`latest_seq` 返回全局最大值

- 文件：`src/lib.rs`
- `do_list_events` 中 `latest_seq` 改为查 `SELECT COALESCE(MAX(seq), 0)`
- 修复前：受 `limit` 参数影响，`limit:1` 时只返回第一个事件的 seq
- 修复后：始终返回该 session 的全局最大 seq，增量轮询基线正确

## clients/weft_client（Flutter）

### 实时执行步骤展示

- `lib/core/api/weft_claw_api.dart`：新增 `getStreamEvents()` 方法，走 `/api/stream/events`
- `lib/core/providers/chat_provider.dart`：
  - 发消息前先拉基线 `latest_seq`，跳过历史事件
  - 轮询改用 `getStreamEvents`（lock-free），200ms 间隔增量追加
  - `_buildSteps` 重构为 `_applyEvents`，接受可变列表做增量追加
  - `tool.started` 立刻追加 Running… 条目；`tool.finished` 替换为结果
  - send 完成后强制把残留 Running… 标记为完成（`—`）
  - 去除打字机动画，回复直接完整显示
- `lib/features/chat/chat_screen.dart`：
  - `_ExecutionStepsPanel` 新增 `forceExpanded` 参数，streaming 时自动展开
  - 工具执行中显示 `CircularProgressIndicator` + "Running…"
