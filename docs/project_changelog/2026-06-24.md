# 2026-06-24 重大更新

## 通信与架构

### FFI 进程内嵌入(零子进程)
- **flutter_rust_bridge** 集成:core 编译为 `weft_core.dll`(cdylib),Flutter 客户端通过 FRB 直接调用
- core 完整 runtime(HTTP server + WASM packages + orchestrator)在客户端进程内运行,**不再需要手动启动 weft-core.exe**
- 用户双击 `weft_client.exe` 即全功能可用
- `main.rs` 启动逻辑抽取到 `runtime.rs`,binary 和 DLL 共用

### 统一通信协议
- 定义 `RequestEnvelope`/`ResponseEnvelope` 信封格式(路径+方法+body)
- Core `/rpc` 统一端点:内部 dispatch(router.oneshot,不走网络回环)
- FFI `rpc_call`:同样走 `dispatch_internal`,零网络延迟(~10-50μs)
- `FfiDioAdapter`:透明拦截所有 Dio 请求走 FFI,上层 API client 零改动
- `TransportAdapter` 抽象层:支持 HTTP/FFI 可插拔,未来可扩展 WS/Pipe

### 端口变更
- 默认端口从 3004 改为 **17830**(config.toml + 前端 + webview 全部更新)

## 功能

### 多 agent 编排修复
- B1: handoff `failed`/`rejected` 状态被接受(之前冻结编排)
- B2: 评审失败不再静默转 approve(改记 reject)
- B3: board 索引损坏时上报(不再静默空转)
- B4: 编排面板显示错误/空态 + 轮询 15 分钟封顶 + 完成即停

### 会话工作区
- `fs_write`/`fs_read`/`fs_list`/`shell_exec` 相对路径解析到 `data/workspaces/<session_id>/`
- 绝对路径/`~` 路径不受影响
- delegate 团队继承发起会话工作区

### Scene 后端
- `AppSceneConfig` 加 `role_routing` + `workspace` 字段
- `bind_scene` 激活时联动写 KV `team:role_routing`
- DELETE 端点 + 禁删 active scene 保护
- `WasmHandle::kv_set/kv_get` 供 API 层直接操作 KV

### Provider 管理
- API key 可见(get_provider 返回完整 keys)
- 模型多选 FilterChip + 搜索 + 手动输入
- 「获取模型」按钮(`/api/providers/fetch-models` 端点)
- Provider 列表页正确显示 key 数(keyCount 字段)
- Provider 保存不再报错(updateProvider 返回值处理)

### 批量会话管理
- `delete_sessions` 批量端点(支持 ids 列表或 all=true)
- 前端多选 + 清空全部

### Package UI
- 动态探测 `/packages/{name}/ui/index.html`(不写死)
- 有 web UI → webview 加载;无 → 诊断页
- Dart extension/plugin 方式废弃,全走 webview

### 其它
- registry 服务上线 `registry.alhz.org`(Postgres + HTTPS + Let's Encrypt)
- memory 包禁用(runtime=none,不再启动 .ps1 黑框)
- Windows 子进程全加 `CREATE_NO_WINDOW`(services/taskkill/shell_exec/pwsh 检测)
- token 读取修复(从 exe 路径向上遍历)
- DLL 自动部署(CMakeLists INSTALL step)
