## ~~5.0 为什么要做垂直版？~~ ❌

> **2026-05-27 决策：拒绝** — 行业垂直层全部打回。

| 维度 | 通用版 | 垂直版 |
|---|---|---|
| 客户认知 | "这是个工具" | "这是为我行业做的解决方案" |
| 客单价 | ¥39-99/月 | ¥299-2999/月 |
| 转化率 | 5% | 20-30% |
| 流失率 | 5%/月 | 1-2%/月 |
| 渠道 | 互联网投放 | 行业 KOL / 协会 / 媒体 / 展会 |

**判断标准**（一个行业值得做垂直版的 4 个条件）：
1. 单一痛点足够清晰
2. 客户付费能力强（B2B 优先）
3. 数据 / 知识有壁垒（可沉淀私有 KB）
4. 我们团队对该行业有认知 / 顾问资源

## ~~5.1 WEFT Code（程序员版）~~ ❌

> **2026-05-27 决策：拒绝** — "全部打回，一个不批准。不做解释。"

> ~~**目标用户**：独立开发者、外包团队、中小研发团队~~
> ~~**客单价**：¥199-999/月（个人）/ ¥1999-9999/月（团队）~~

### 核心场景
- **代码评审 Bot**：PR / MR 自动评审，发表评论
- **私有仓库 RAG**：把全公司代码索引化，"这个功能在哪个模块" 一查就到
- **AI 结对编程**：Cursor 平替，但跑在自己账户和上下文里
- **自动化测试生成**：根据代码自动生成单元测试 + 集成测试
- **依赖升级 Bot**：自动跟踪 npm / pip / cargo 包升级 + 修兼容性
- **文档自动同步**：代码变更后自动更新 README / API 文档
- **Bug 复现机器人**：根据 issue 描述自动复现 + 给出 hypothesis

### 行业模板（开箱即用）
- "新员工 Onboarding Agent"：自动讲解代码库
- "技术债跟踪器"：定期扫描 + 生成报告
- "API 变更通知"：监控 OpenAPI / 协议变更

### 私有 KB
- 代码语义索引（用 tree-sitter + 代码 embedding）
- 提交历史 + Issue 上下文
- 团队规约 + 架构文档

### 集成
- GitHub / GitLab / Gitea / Bitbucket
- Jira / Linear / 飞书项目
- IDE 插件（VS Code / JetBrains / Neovim）

### 复用 WEFT-plug 已有能力
- **直接复用 `weft-code` 产品 runtime**（已有 TUI + WASM 包）
- Code Agent 走 `agent-core` + `tool-runtime-core`
- 代码搜索复用 KB 层 + 加 tree-sitter 索引

### 优先级
**P0**（我们团队天然懂，第一个上线）

## ~~5.10 通用：行业版的统一框架~~ ❌

> **2026-05-27 决策：拒绝** — 行业垂直层全部打回，统一框架不再适用。

### ~~每个行业版的共同结构~~
1. **专属 Onboarding**：用行业语言引导，3 步上手
2. **行业 KB 预置**：法规 / 案例 / 模板开箱即用
3. **行业 Agent 包**：5-10 个核心 Agent
4. **行业工作流模板**：10-30 个开箱模板
5. **行业集成**：常用 SaaS / 工具的连接器
6. **行业定价 / 套餐**：去掉用不到的功能、加上行业刚需
7. **行业销售 + 客户成功**：专属团队 / 顾问

### 复用底层 = 80% 工作量，行业差异 = 20%
- 复用：RC 账户 / Agent 引擎 / KB / 云函数 / 多模态
- 行业差异：UI 主题 / 模板 / Prompt 库 / 集成 / 销售

### 商业化考虑
- 每个行业版独立品牌（如 weft.codes / studio.weft.app）
- 共享底层账户（用户买了 Code 也能用 Studio）
- 主站推荐 + 交叉销售

## ~~本章小结~~ ❌

> **2026-05-27 决策：全部归档** — 行业垂直层全部打回，以下结论不再有效。

### ~~一年内重点做的 2 个垂直版~~
1. **WEFT Code**（我们最懂、用户最重叠、最先盈利）
2. **WEFT Studio**（多模态变现快、内容传播力强）

### 第二年扩展的 2 个
3. **WEFT Office**（覆盖最广）
4. **WEFT Research** 或 **WEFT Commerce**（看哪边商业资源更充分）

### 暂不碰或后置
- **Legal / Health / Edu / Finance**：合规重，先观察

### 核心原则
> "**底层做透**，**垂直做精**"
>
> 不做泛而平庸，做窄而深。每个垂直版都要让客户觉得"这是我行业的工具"，而不是"通用 AI 工具装了个皮"。
