## 4.1 Agent 配置 / 编排器 ✅

> **2026-05-27 决策：通过** — 核心功能，保留。

### 功能描述
- 可视化配置 Agent：
  - 系统 Prompt
  - 模型档位（经济 / 标准 / 高级 / 旗舰）
  - 可用工具集（fs / shell / web_search / 自定义 MCP / 自定义函数）
  - 知识库绑定（绑定特定 KB 做 RAG）
  - 触发器（HTTP / Cron / Webhook / 手动）
  - 输出格式（Markdown / JSON / 流式）
- "对话即配置"：用户和一个 meta-Agent 对话，meta-Agent 帮用户生成新 Agent

### 用户价值
- 不写代码也能搭专业 Agent
- 资深用户也能调用 YAML / API 高效定制

### 技术实现（基于 WEFT-plug）
- **直接复用 `agent-core` WASM 包的 turn loop**（已有 6400 行实现）
- 前端用 Vue 3 + Pinia（已有 Electron 客户端基础）
- Agent 配置存 PostgreSQL，运行时加载到内存

### 优先级
**P0**（生态层入口，必须早做）

## 4.2 Agent 长任务托管 ❌

> **2026-05-27 决策：拒绝** — "不符合我们产品定位"

### 功能描述
- Agent 可以跑数小时甚至数天的任务
- 用户提交后可关闭浏览器，平台后台跑
- 支持中途暂停 / 恢复 / 取消
- 实时进度推送（WebSocket / 邮件 / IM）
- 失败自动重试 + 状态快照

### 用户价值
- 监控网站 24 小时、爬取 1 万条数据、分析整本书 - 这些场景一次解决
- 区别于 ChatGPT 的"等不了就断了"

### 技术实现
- 任务调度：Temporal / 自研基于 NATS
- 状态持久化：每步 turn 后写入 DB
- 沙箱长驻：复用 Firecracker microVM
- 复用 `weft-claw` 的 `cancel_turn` 能力

### 定价建议

| 计量项 | RC |
|---|---|
| Agent 调用 | LLM token + 工具调用费 |
| 长任务挂起（每小时） | 5 |
| 状态快照存储 | 30/GB·月 |

### 优先级
**P1**（M4-M5）

## 4.3 多 Agent 协作沙箱 ❌

> **2026-05-27 决策：拒绝** — "多 agent 协作也没必要"

### 功能描述
- 多个 Agent 在同一个沙箱内协作（如：Planner + Coder + Reviewer + Tester）
- 共享文件系统、共享上下文、消息总线通信
- 支持组织模式：
  - **Pipeline**（流水线）
  - **Debate**（辩论 / 多视角）
  - **Hierarchy**（主从）
  - **Marketplace**（拍卖型任务分配）

### 用户价值
- 让用户能搭"AI 部门"
- 复杂任务效果远超单一 Agent
- 企业版核心卖点

### 技术实现
- 类似 OMC `omc-teams` / `team` 的多 Agent 协作骨架
- 沙箱共享内存通过 shared_memory 模块（OMC 已有原型）

### 优先级
**P2**（M6-M8，前面铺好基础后做）

## 4.4 可视化工作流编排（类 Coze / n8n） ❌

> **2026-05-27 决策：拒绝** — 明确拒绝
> 不做可视化工作流编排器。

### 功能描述
- 拖拽节点搭建自动化工作流：
  - **触发器节点**：Webhook / Cron / 邮件 / IM 消息 / 文件上传
  - **AI 节点**：LLM / 搜索 / 图像 / 转写
  - **逻辑节点**：条件 / 循环 / 分支 / 等待
  - **数据节点**：数据库读写 / API 调用 / 知识库检索
  - **输出节点**：邮件 / IM / Webhook / 数据库 / 文件
- 实时执行 + 可视化调试
- 模板市场（见 4.7）

### 用户价值
- 把 Zapier / Make / n8n / Coze 的能力一站式提供
- 非程序员也能搭复杂自动化

### 技术实现
- 前端：Vue Flow / React Flow
- 执行引擎：基于 agent-core 改造
- 节点定义走 WASM 包系统（每个节点是一个能力）

### 定价建议
- 按节点执行次数计费：
  - 简单节点（条件 / 数据库读）：0.1 RC/次
  - AI 节点：按模型档位
  - 高级节点（图像 / 视频）：按子服务
- 工作流挂起 / 等待：免费

### 优先级
**P1**（M4-M6）

## 4.5 Agent 市场 / 工作流市场 / MCP 市场 ❌

> **2026-05-27 决策：拒绝（不单独定义）** — "拒绝或者不单独定义"
> 不单独定义三类市场。生态分发由 mod / plugin 机制承载。

### 功能描述
- 三个市场并行：
  - **Agent 市场**：用户上架 Agent，他人订阅 / 调用
  - **工作流市场**：模板化的 workflow 商店
  - **MCP 市场**：第三方 MCP Server 上架（接外部工具：Notion / Linear / 飞书 / Google Drive 等）
- 上架审核 + 评分 + 评论 + 关注 + 推荐算法
- 创作者中心：收益 / 调用统计 / 用户反馈

### 用户价值
- **C 端**：不用自己写，挑现成的
- **创作者**：技能变现（写一个好 Agent 月入数千）
- **平台**：网络效应 + 内容护城河

### 技术实现
- 上架 = 把配置打包成 WASM 包（已有包系统支持）
- 审核走人工 + AI 双层
- 推荐走点击率 + 留存率综合排序

### 定价 / 抽成

| 模式 | 抽成比例 |
|---|---|
| 用户订阅 Agent（月费） | 平台 30% / 作者 70% |
| 单次调用付费 Agent | 平台 30% / 作者 70%（叠加底层算力费用） |
| 免费 Agent | 不抽成（作者只赚流量） |
| 工作流模板（一次性购买） | 平台 30% / 作者 70% |
| MCP Server 调用 | 平台 30% / 作者 70%（叠加调用次数费） |

### 竞品参考
- OpenAI GPT Store（不抽成但有创作者基金）
- Coze / 扣子（免费但流量受限）
- Poe（创作者分成模式）

### 优先级
**P0**（核心生态卖点）

## 4.8 Agent 评测与监控 ✅

> **2026-05-27 决策：通过** — 默认保留。

### 功能描述
- 给 Agent 做"单元测试"：
  - 设定测试用例（输入 → 期望输出）
  - 自动运行 + 评分
  - 回归检测（模型升级 / 配置变更后跑）
- 在线监控：
  - 调用量 / 错误率 / 延迟分布
  - Token 消耗趋势
  - 用户反馈聚合

### 用户价值
- 让 Agent 可以像软件一样持续迭代
- 企业用户必备（Agent 上线后效果不能退化）

### 技术实现
- 评测引擎复用 LLM-as-a-judge 模式
- 监控走 OpenTelemetry + Prometheus

### 优先级
**P2**（M7-M9，企业销售加码）

## 本章小结

Agent / 自动化层是**生态层**的核心：

1. **配置即创造**：用户用对话生成 Agent，再用工作流编排 Agent
2. **市场即变现**：Agent / 工作流 / MCP 三个市场齐头并进
3. **演化即护城河**：Evolved Skill 让 Agent 越用越好
4. **安全即信任**：沙箱 + 审计 + 权限分层

平台收入结构会从这里开始变化：**前期靠 RC 充值，后期靠 Agent 抽成**。一旦市场起飞，Agent 抽成会反超充值收入，毛利率达 60%+，且具备 winner-takes-most 的网络效应。

> "We don't just sell AI. We sell the marketplace of AI applications."
