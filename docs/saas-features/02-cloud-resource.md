## 2.1 Serverless 云函数

### 功能描述
- 用户输入自然语言 → AI 写代码 → 沙箱（WASM / Container）部署 → 返回公网 URL
- 支持运行时：Python / Node.js / Go / Bash / WebAssembly
- 触发方式：HTTP / Cron / Webhook / 事件总线
- 内置环境变量、Secrets 管理、日志查看、版本回滚

### 用户价值
- 写"接受 webhook 转发到飞书"这种小工具，从"租 VPS → 配 Docker → 写 nginx → 写代码"压到 30 秒
- 真正实现"AI 创建即托管"，区别于 Vercel / Cloudflare（这些还要用户自己写代码）

### 技术实现（基于 WEFT-plug）
- 复用 `tool-runtime-core` 的沙箱执行能力（已支持 fs/shell/python）
- 增加 WASM Runtime（Wasmtime / Wasmer）做强隔离
- 部署层：K8s + KEDA 自动扩缩
- 路由层：自动签发 `<func-id>.weft.app` 子域名

### 定价建议（RC = ¥0.01）

| 计量项 | RC |
|---|---|
| 调用次数（≤ 1s，128MB） | 0.1/次 |
| 内存×时间（超额部分） | 0.05/GB·秒 |
| 出网流量 | 50/GB |
| 部署存储（代码包） | 免费 ≤ 100MB，超出 5 RC/100MB·月 |

> 免费额度：每月 10000 次调用 + 100 GB·秒（覆盖 90% 个人用户）

### 竞品参考
- Vercel Functions（$20/月起）、Cloudflare Workers（$5/月起）、AWS Lambda（按量）
- **差异化**：我们是"AI 直接产出 + 托管"，Vercel/CF 是"你自己写好上传"

### 优先级
**P0**（核心差异化卖点）

## 2.2 静态网站托管

### 功能描述
- AI 生成 HTML/Vue/React/Next → 自动构建 → 部署到 CDN
- 自定义域名 + 自动 HTTPS + 全球边缘加速
- 内置主题切换、表单提交、访客统计

### 用户价值
- "帮我做一个本月的活动页"→ 2 分钟内出公网链接
- 个人 portfolio / 落地页 / 小工具站点

### 技术实现
- 静态文件存对象存储（自建 MinIO 或 R2）
- CDN 选 Cloudflare（全球）+ 腾讯云 CDN（国内）双轨
- 域名管理走 DNSPod / Cloudflare API
- HTTPS 证书自动 ACME 签发（Let's Encrypt）

### 定价建议

| 计量项 | RC |
|---|---|
| 部署（构建一次） | 5/次 |
| 存储 | 30/GB·月 |
| 出网流量（CDN） | 100/GB |
| 自定义域名 | 免费（Pro 套餐内）/ 单独 50/月 |

### 竞品参考
- Netlify、Vercel、Cloudflare Pages、GitHub Pages
- **差异化**：和 AI 创作工具打通，"边改边发布"

### 优先级
**P1**（M3-M4）

## 2.3 托管数据库（DBaaS）

### 功能描述
- 三种数据库即开即用：
  - **PostgreSQL**（关系型，主推）
  - **SQLite**（轻量，函数自带）
  - **Vector DB**（基于 Qdrant，给 RAG 用）
- 自然语言建表：用户说"我需要一个用户表存邮箱、注册时间、积分"，AI 自动出 schema + 建表
- 自动备份、点时间恢复、连接池

### 用户价值
- AI 写完代码不用再配数据库
- 个人项目 / Hackathon / 内部工具直接跑

### 技术实现
- PostgreSQL：自建 K8s 集群（CloudNativePG operator）
- Vector DB：自建 Qdrant 集群（替代 Pinecone，成本砍 60%）
- 多租户：每个用户独立 schema（共享实例）/ 独立实例（付费）

### 定价建议

| 类型 | 规格 | RC/月 |
|---|---|---|
| PG 共享 | 1GB 存储 | 500 |
| PG 独享 | 1 核 2G 10GB | 5000 |
| Vector DB | 100 万向量 | 1500 |
| SQLite | 单文件 ≤ 1GB | 免费 |

### 优先级
**P1**（M4-M5）

## 2.5 定时任务 / Cron

| 计量项 | RC |

| 单次触发 | 0.5/次 |

## 本章小结

云资源层是**让 AI 从"出建议"升级到"出结果"的关键**。

设计原则：
1. **AI 优先**：所有资源都能从自然语言一步创建
2. **统一计费**：函数 + 存储 + 数据库 + 流量统一走 RC
3. **零运维**：用户不接触 K8s / nginx / 证书 / cron 表达式
4. **生产可用**：备份、监控、告警、日志一应俱全

这一层做扎实，第五章"行业垂直版"才有底气支撑（比如"自媒体版"自动建站 + 自动发布）。
