## 1.1 多模型聚合 + 智能路由 ❌

> **2026-05-27 决策：拒绝** — "no need we have but deepseek"
> 当前只接入 DeepSeek，不做多模型路由。底层 fork 自 new-api 的 channel 适配器保留代码（rebase 友好），但客户端只暴露 DeepSeek 路径。

### 功能描述
- 后端聚合 DeepSeek / Claude / GPT / Gemini / Qwen / GLM / Kimi / 豆包等 10+ 主流模型
- 用户调用时只选"档位"（经济/标准/高级/旗舰），平台自动路由
- 支持三种路由策略：**质量优先 / 价格优先 / 速度优先**
- 自动 failover：A 厂商挂了自动切 B 厂商，对用户无感

### 用户价值
- 用户只懂"我要个聪明 AI"，不需要懂模型差异
- 单家 API 限流/抖动时不影响业务连续性
- 同档位不同任务自动选最优模型，平均省 20% 成本

### 技术实现（基于 WEFT-plug）
- 复用 `agent-core` WASM 包的工具调用编排能力
- 在 `server/router/api-router.go` 增加 `/v1/chat/completions` OpenAI 兼容入口
- 路由层用 `server/model/option.go` 的能力注册表存模型元数据
- 实时监控各供应商延迟/错误率，写入 Redis 做秒级路由决策

### 定价建议（RC = ¥0.01）

| 档位 | 输入 RC/1K token | 输出 RC/1K token | 毛利 |
|---|---|---|---|
| 经济档 | 0.02 | 0.04 | 30% |
| 标准档 | 0.20 | 0.40 | 25% |
| 高级档 | 0.40 | 2.00 | 20% |
| 旗舰档 | 2.00 | 10.00 | 15% |

### 竞品参考
- OpenRouter（5% 加价）、硅基流动（无加价靠规模）、302.AI（积分制 1.5-2x）

### 优先级
**P0**（已部分实现，2 周内完成多家接入）

## 1.2 BYOK（Bring Your Own Key）路由 ✅

> **2026-05-27 决策：通过** — "nb, sounds good"

### 功能描述
- 用户绑定自家 OpenAI / Anthropic / DeepSeek API Key
- 平台只收 **5% 路由服务费**（按 token 折算 RC 扣减）
- 享受平台所有上层能力（Agent / 工作流 / 知识库 / 审计）

### 用户价值
- 大客户 / 企业 / 开发者已有 Key 不用浪费
- 价格敏感用户的"廉价升级方案"
- 公司报销 / 财务审计需要原厂账单的用户

### 技术实现
- `server/model/user.go` 增加 `byok_keys` JSONB 字段（加密存储）
- 调用链路：用户请求 → 路由层判定 BYOK → 用用户 Key 转发 → 计费按 5% 折扣

### 定价建议
- BYOK 调用：实际 token 价值 × 5% → 折成 RC
- 例：调用 GPT-5.4 用了 $1，扣 RC = $1 × 5% / $0.0014 ≈ 36 RC

### 竞品参考
- Cursor BYOK 模式（不收 token 费仅订阅）、OpenRouter 部分支持

### 优先级
**P1**（M2-M3）

| LLM 优化（Tavily） | 10 |

## 1.8 Prompt 缓存 + 重复请求折扣 ✅

> **2026-05-27 决策：通过** — 默认保留

### 功能描述
- 相同 prompt（含上下文）命中近因缓存（30 分钟内）退还 50% RC
- Anthropic / OpenAI 自带的 prompt cache 也透传给用户

### 用户价值
- 调试 / 重复运行场景省一半钱
- 用户感知"这平台真的省钱"

### 技术实现
- Redis 缓存 prompt hash → response
- 计费时识别命中 → 退还 RC 到账户

### 商业意义
- 既省了平台上游成本，又给用户好感（双赢）
- 是"低价获客"的合规手段（不打价格战）

### 优先级
**P1**

## 本章小结

AI 能力层的关键不是"接更多模型"，而是：
1. **统一抽象**（OpenAI 协议 + 档位）
2. **统一计费**（RC + 命中缓存退款）
3. **统一可观测**（路由决策 / failover / 成本透明）

这一层做扎实，才能支撑后续所有上层产品。
